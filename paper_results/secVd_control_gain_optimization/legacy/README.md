# Legacy Section Vd provenance

Archival material for issue #154: the program that produced the Section Vd
results published in the preprint, and two scripts that verify what it was.

Nothing here is part of the current workflow. The current optimizers, plotter and
renderer live in [`../code/`](../code/).

## Why this directory exists

PR #68 committed six-start MATLAB result archives without the code that produced
them. The generators in the repository at that time were single-start, so the
published Section Vd numbers could not be regenerated by anything committed. The
follow-up on #154 additionally found that the stored losses were about an order
of magnitude below what the committed objective scored the same trajectories at.

The generator was recovered in September 2026 from the author's machine. It is
kept here rather than left on a laptop, because a generator that exists only
outside version control is exactly how this was lost the first time.

## Contents

| file | what it is |
| --- | --- |
| `soromox_synergistic.py` | The recovered generator, byte-for-byte. **Not executable against current soromox.** |
| `rescore_legacy_archives.py` | Re-derives both legacy objectives from the archived trajectories. Pure NumPy; runs anywhere. |
| `reproduce_legacy_initialization.py` | Re-runs the generator at its initialization and matches the archive. Needs an old soromox tree. |

`soromox_synergistic.py` is committed verbatim, including its original CRLF line
endings, and is excluded from ruff and from Git's end-of-line normalization
(see `.gitattributes` and `pyproject.toml`) so that the archived bytes are the
bytes that produced the results.

**Only its `generate_mixed_batch` function and its parameter blocks are
authoritative.** It imports `soromox.systems.tendon_actuated_pcs`, removed by
PR #117, and a local `utils` package that was never committed; its optimization
loop also carries a bug described below. Read it as evidence, not as an example.

## What the two scripts establish

### `rescore_legacy_archives.py`

Needs no soft-robot model — only the archived trajectories and their reference.

**The collocated objective is recovered exactly**, reproducing all twelve stored
losses to `6.1e-16` relative:

```text
loss = 1e2 * ∫₀^2.5 eᵀWe dt + 2e2 * ∫_2.5^5 eᵀWe dt,   W = diag([1, 1, 1, 100, 100, 100])
```

`W` is not a tuning constant. With the segment length `L = 0.1 m`,
`W = (1/L²)·diag(L², L², L², 1, 1, 1)`, so `eᵀWe = ‖ê‖²/L²` for
`ê = [L·e_κ ; e_σ]`. The legacy collocated objective is exactly the strain error
**non-dimensionalized by segment length** — the physically motivated
normalization the follow-up asked for, already present in the legacy data. Its
global factor is `1e2` and its early/late ratio is **1:2**.

**The synergistic objective** uses `1e3` and `5e3` — ratio **1:5** — plus a
strictly positive additive remainder in `[0.096, 0.623]`.

### `reproduce_legacy_initialization.py`

Re-runs the generator forward at its six recovered initializations. All six match
`history_loss[0]` to **≤1.8e-9** relative, which is solver noise over 50000
steps. This simultaneously pins the initialization, the objective, the robot and
the controller conventions. The remainder above is confirmed to be exactly
`2.5·∫P_t² dt`, the tendon-power penalty: `2.5 × power_integral` from the re-run
equals the residual measured by `rescore_legacy_archives.py` to every digit.

```bash
git worktree add /tmp/soromox-legacy backup/main_resolve_upon_time
PYTHONPATH=/tmp/soromox-legacy/src JAX_PLATFORMS=cpu \
  python paper_results/secVd_control_gain_optimization/legacy/reproduce_legacy_initialization.py
```

The `backup/main_resolve_upon_time` branch is the last tree carrying both
`TendonActuatedPCS` and `resolve_upon_time`. Three helpers from the author's
uncommitted `utils` package are reimplemented in the script:
`utils.controllers.PID`, and `utils.algebra.{manip_index, cond_number}`.
`cond_number` only fed a logged diagnostic. `manip_index` only gates the damping
of the synergy inverse, and along this rollout the index is ≥ 0.598 against a
threshold of 0.1 under every candidate definition, so the damping is identically
inactive and the missing definition provably cannot change the result.

## The legacy MAT archives

PR #149 replaced them with the NPZ workflow, so they are no longer reachable by
path on any branch. Both scripts address them by content-addressed blob SHA,
which survives branch movement and deletion:

```bash
git cat-file blob 6fbaac30c471f4e751fcc8cc73ff0d746110e65a > collocated.mat
git cat-file blob 621f9c76902468bbd324ce5a880b860e4a4b9b6f > synergistic.mat
```

They carry a `PCWIN64` header and a single shared timestamp, and hold only five
variables each. The generator writes far more than that via
`scipy.io.savemat` — including the `hist_opt_ctr_params_*` gain histories. The
committed archives are therefore a **subset re-saved from MATLAB**: the gains
were written by the generator and then discarded downstream, which is why the
initialization could not be read back out of them.

## Defects in the legacy run

Recorded because they bear on how the published numbers should be read.

- **The optimizer state was stale.** Line 550 assigns the updated state to
  `updated_opt_state` while the loop keeps passing `opt_state`, so the Yogi
  moments stay frozen at their iteration-1 value for the remaining 99
  iterations. The published run was not a standard Yogi run.
- **Gains and losses are off by one** (issue #129). The loss at history index
  `j` is evaluated before the update whose parameters are appended at index `j`.
- **`q_ts_best` / `x_ts_best` are not per-start bests.** They are the whole batch
  captured at the single globally best iteration, which is iteration 99 in both
  archives.
- **The two archives are not from the same robot.** The synergistic generator
  drives a two-segment robot; its tip at `q = 0` is `[0, 0, 0.20]`, matching the
  archive bit-for-bit. The collocated archive stores 6-DOF configurations, so it
  came from a one-segment robot.
- **The two objectives are not comparable**, as shown above: different global
  factors, different early/late ratios, one with a strain weighting and one with
  a power penalty. The plotter's historical division of the collocated loss by
  100 was cosmetic axis alignment, not a normalization.

Consequently the published 62% / 57% reductions cannot be regenerated by the
current workflow, and should be read as belonging to the legacy models. See the
provenance section of [`../README.md`](../README.md).
